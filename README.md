# 我的影评记录

一个面向个人使用的电影档案。Windows 桌面版双击 EXE 即可打开独立窗口，无须启动本地服务，也不会监听网络端口；网页版改造代码位于 `web/`，需单独部署和登录。

界面采用“暗色影院档案馆”主题：暖黑背景、酒红主色、香槟金强调与低饱和青绿知识图谱节点。

## 功能

- 录入、编辑、删除影评，点击卡片在独立弹窗查看完整详情
- 影评详情左右提供上一个/下一个导航，并支持键盘左右方向键按当前筛选与排序浏览
- 每条影评可保存一张 JPG、PNG 或 WebP 原始剧照，可点击选择或从 Windows 资源管理器拖入；全屏查看时可缩放和拖动查看局部
- 已有影评可通过“记录重看”填写时间、独立评分与当次感受，支持调整或删除，并以曲线展示观感变化
- 按电影名、导演、评论或标签搜索
- 按评分和标签筛选，按日期、评分或名称排序
- 策展墙提供电影节点与关系节点组成的 Canvas 知识图谱，可切换电影风格、导演、观影年份、评分、重看状态或补充标签，并保留高密度海报墙
- 展示观影总数、平均评分、本月观影数和分类数
- 首页“历史上的今天”展示往年同日观影记忆；没有周年记录时推荐一年以上未看的高分电影
- “品味画像”在本地统计分类、导演、评分、重看率、年度观影和代表电影，并说明每项计算依据
- 可记录观看地点、同行人、心情、人生阶段、影响、难忘场景、台词、推荐对象和再次重看意愿
- 年度报告按年份汇总初看、重看、评分、分类、导演和月度分布，并可导出独立 HTML
- 档案健康度检查缺失字段、日期异常、疑似重复和分类别名，支持确认式批量分类合并
- 海报墙可把当前筛选下的全部电影导出为 PNG；知识图谱可导出为离线互动 HTML，在浏览器中点击节点查看关联电影
- 首次启动选择数据目录，之后可随时切换
- 导出包含 JSON 与剧照的完整 ZIP 备份，同时兼容导入旧版 JSON
- 每次修改前自动保留 JSON 历史版本，最多保留 20 份
- 桌面版数据只保存在本机，不自动上传；网页版使用独立的服务器数据库和媒体目录

## 直接使用

1. 从 GitHub Releases 下载 `我的影评记录.exe`。
2. 双击运行，首次启动时选择一个数据保存目录。
3. 如已有旧版数据，请选择包含 `movie-reviews.json` 的目录；程序会直接读取它。

数据目录内的主文件是 `movie-reviews.json`，剧照位于 `media` 子目录，历史 JSON 版本位于 `backups` 子目录。剧照按内容哈希保存，同一图片不会重复复制；更换剧照或删除影评时旧图片仍会保留，以便历史版本恢复。建议把数据目录放在你日常备份的位置。应用设置仅记录所选目录，保存在 `%APPDATA%\MovieReview\settings.json`。

剧照为可选项，单张最大 50 MB，保留原始画质及 EXIF/GPS 等元数据。在新建或编辑影评时，可点击“选择剧照”，也可将 Windows 资源管理器中的一张 JPG、PNG 或 WebP 直接拖到主剧照区域。需要迁移或备份时，请使用应用顶部的“导出”，生成同时包含当前 JSON 和被引用剧照的 ZIP，不要只复制 JSON。

> Windows 10/11 通常已经包含 Microsoft Edge WebView2 Runtime。若窗口无法打开，请先安装微软官方 WebView2 Runtime。

## 本地开发

要求 Windows 与 Python 3.10 或更高版本：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

运行测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## 构建单文件 EXE

```powershell
.\build.ps1
```

构建产物位于 `dist\我的影评记录.exe`。PyInstaller 单文件程序启动时会临时解包内部运行文件，因此应用界面被打进 EXE，而用户数据始终写入首次选择的外部目录。

## 网页版开发与部署准备

网页版复用现有页面和字段校验，支持多用户登录、管理员用户管理、用户独立档案、符合三范式的 SQLite 关系表、逐条保存与版本冲突检查、私有剧照、导入导出和服务器备份。管理员可以创建、编辑、停用用户及重置密码；每位用户只能访问自己的影评和媒体。它不会自动同步桌面版的日常修改。当前仓库提供代码和部署模板；正式服务器发布、离机备份与手机实机验收须在实际服务器完成。

在单独的 Python 3.12 环境安装 `requirements-web.lock`，用 `python -m web.manage --data-dir <网站数据目录> init-account --username <账户>` 交互创建账户。设置 `MOVIE_REVIEW_DATA_DIR` 后，以 `python -m uvicorn web.main:app --host 127.0.0.1 --port 8000` 在本机启动试验服务。公网入口只通过部署方案中的 HTTPS 代理开放，不直接开放 8000。

首个账户为管理员。点击页面右上角头像，可进入“个人中心”“账户安全”，管理员还可进入“用户管理”。个人中心展示真实的观影概况、最近记录和档案工具，支持修改显示名称；登录账户名由管理员管理。用户管理提供名称搜索、角色与状态筛选，桌面端并排显示列表和编辑区，手机端从列表进入编辑后可返回。重置密码、变更登录账户、角色或启用状态前会显示确认说明，未保存的用户资料在离开前会提示。

网页用户模块的样式位于 `web/account.css`，仅由网页服务加载。资料编辑复用现有用户表，不需要新一轮数据库结构迁移。旧网站库升级前需停止写入并保留完整备份；新版提供 `python -m web.manage --data-dir <网站数据目录> upgrade-db`，也会在首次打开旧库时执行带备份的事务迁移。结构、三范式依据及回滚顺序见 [数据库模型说明](docs/DATABASE_MODEL.md)。

网页版接口测试用已安装 Web 依赖的解释器运行 `python -m unittest discover -s tests -p test_web.py -v`。桌面专用环境未安装 Web 依赖时，通用测试发现会跳过 Web 测试；上线发布必须在 Web 环境单独运行并确认通过。

历史数据先运行 `python -m web.manage preflight <桌面数据目录>`，再从原始目录副本迁入全新目标目录；具体顺序见 [部署准备说明](deploy/README.md) 和 [数据库模型](docs/DATABASE_MODEL.md)。旧版桌面数据与备份原件应保留。

## Git 发布与服务器上线

后续代码通过本地 Git 提交并推送到 `origin/main`，服务器从 Git 拉取指定的完整提交 SHA，再执行测试、备份恢复演练和版本切换。操作规范、首次接入与回滚见 [Git 发布与服务器上线流程](deploy/GIT_RELEASE.md)。

```powershell
.\deploy\publish.ps1 -Message 'fix: 描述本次改动'
```

本地发布完成并确认 CI 成功后，在服务器执行 `sudo movie-review-deploy <完整提交SHA>`。数据库、媒体、生产配置和私钥保存在 Git 外；发布失败会恢复原代码，保留最新数据。历史 ZIP/bootstrap 脚本留作首次安装与历史证据。

## 项目结构

- `app.py`：数据校验、原子保存、滚动备份和桌面桥接
- `index.html`：内嵌桌面界面
- `movie-review.spec`：PyInstaller 单文件构建配置
- `tests/`：存储与数据校验测试
