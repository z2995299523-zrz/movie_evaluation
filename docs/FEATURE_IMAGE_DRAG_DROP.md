# 剧照拖拽上传功能优化需求

## 1. 文档信息

- 状态：待实现
- 优先级：P1（体验优化，不阻塞现有功能）
- 适用端：Windows 桌面版
- 依赖功能：单张主剧照、原生图片选择、图片预览、详情弹窗、完整 ZIP 备份
- 本文范围：仅定义需求与验收标准，不代表功能已经实现

## 2. 背景与目标

当前新增或编辑影评时，需要点击“选择剧照”，再通过 Windows 文件对话框选择图片。该流程可靠，但当用户已经在资源管理器中找到剧照时，操作步骤偏多。

本次优化允许用户把资源管理器中的一张图片直接拖到“主剧照”输入区域，系统自动识别、校验、复制并显示预览，同时继续保留现有点击选择方式。

目标：

- 减少从资源管理器添加剧照的操作步骤。
- 拖入后的校验、存储、去重和预览结果与点击选择完全一致。
- 拖拽处理期间保持窗口响应，不重新引入本地 HTTP 服务。
- 不改变 `movie-reviews.json` 的图片字段结构和 ZIP 备份格式。

## 3. 非目标

- 不支持一次上传多张剧照。
- 不支持从网页直接拖入网络图片或图片链接。
- 不支持从微信、浏览器、Outlook 等程序拖出的虚拟附件；第一版只接收 Windows 文件系统中真实存在的本地文件。
- 不支持拖入文件夹、压缩包、视频、剪贴板图片或纯文本。
- 不增加图片裁剪、压缩、旋转、格式转换和元数据清理。
- 不改变“每条影评最多一张主剧照”的产品约束。

## 4. 用户场景

### 4.1 新增影评

1. 用户打开“写新影评”弹窗。
2. 用户从 Windows 资源管理器拖动一张图片。
3. 指针进入主剧照区域后，区域显示可放置状态。
4. 用户释放鼠标。
5. 系统校验文件，通过后复制到当前数据目录的 `media`，并显示预览、文件名、大小和类型。
6. 用户保存影评后，图片引用随影评一起写入 JSON。

### 4.2 编辑并替换剧照

1. 用户编辑已有剧照的影评。
2. 用户把另一张图片拖入主剧照区域。
3. 新图片通过校验后立即替换表单中的待保存图片和预览，不弹出二次确认。
4. 原影评记录在用户点击“保存影评”前保持不变。
5. 用户取消编辑时，影评仍引用旧图片；已经复制的新图片按现有策略保留为未引用媒体。

## 5. 交互需求

### 5.1 默认状态

- 保留“选择剧照”按钮，键盘用户和不使用拖拽的用户仍可完成全部操作。
- 空状态增加提示：“点击选择，或将一张 JPG、PNG、WebP 拖到这里”。
- 有图状态下，整个预览区域仍可接收拖入文件，并保留“更换”“移除”按钮。

### 5.2 拖拽状态

- `dragenter` / `dragover`：输入区域边框切换为强调色，背景轻微高亮，文案变为“释放以上传剧照”。
- `dragleave`：只有指针真正离开整个输入区域时才恢复默认状态，避免经过子元素时闪烁。
- `drop`：立即恢复默认视觉状态并开始校验。
- 文件处理期间禁用“选择剧照”“更换”“移除”，显示“正在读取剧照…”；处理完成后恢复。
- 必须阻止浏览器默认行为，避免 WebView2把图片导航打开或覆盖当前应用页面。

### 5.3 成功反馈

- 使用现有图片预览组件显示结果。
- 展示原始文件名、文件大小和 MIME 类型。
- 图片已存在时复用哈希文件，但用户仍看到正常的成功预览，不需要了解去重细节。
- 保存按钮在图片校验和复制完成前不得提交包含半成品引用的数据。

### 5.4 失败反馈

失败时保留拖拽前的图片选择状态，不清空已有预览，并通过 Toast 显示明确原因：

- 多文件：`每条影评只能上传一张主剧照`
- 文件夹：`请拖入一张图片文件，不支持文件夹`
- 不支持格式：`仅支持 JPG、PNG 和 WebP 剧照`
- 扩展名伪装：`剧照扩展名与实际文件内容不一致`
- 空文件：`剧照文件为空`
- 超过 50 MB：`剧照不能超过 50 MB`
- 文件已被移动、删除或无权限：`无法读取拖入的剧照文件`
- 无法取得本地真实路径：`暂不支持从此程序拖入图片，请先保存到本地再选择`

## 6. 文件与数据规则

- 拖入文件必须复用现有图片导入规则：文件头识别、扩展名一致性、50 MB上限、SHA-256命名、内容去重和原始字节保留。
- 后端新增的拖拽导入入口只能接收本次拖拽事件提供并经验证的本地文件路径，不允许前端构造任意路径读取其他文件。
- 媒体路径继续使用：`media/<sha256>.<jpg|png|webp>`。
- 影评图片字段继续使用现有 `image.path/name/mime/size`，不做数据迁移。
- 拖入成功但未保存影评、替换后取消或移除图片时，不自动删除媒体文件，与当前历史恢复策略保持一致。
- ZIP导出仍只包含当前影评实际引用的图片，未引用拖拽文件不进入完整备份。

## 7. 性能与稳定性

- 拖入视觉反馈应在 100 ms内出现。
- 文件哈希和复制不得在 WebView2 UI线程执行。
- 最大50 MB文件处理期间，窗口可拖动、表单可滚动，进度文案持续更新或至少保持处理中状态。
- 预览继续使用现有分块读取与 Blob URL机制，不一次性通过JS桥传递整张50 MB Base64。
- 用户关闭编辑弹窗时，停止尚未完成的前端预览加载并释放 Blob URL。
- 快速重复拖入时只接受最后一次有效操作，避免并行覆盖表单状态；已经开始的旧任务完成后不得覆盖新图片预览。

## 8. 可访问性与兼容性

- 拖拽只是增强入口，“选择剧照”按钮必须始终保留并可通过键盘操作。
- 拖拽状态不能只依赖颜色，应同时显示文字或图标变化。
- 输入区域提供明确的可访问名称，例如“主剧照上传区域”。
- Windows缩放比例为100%、125%、150%时，拖拽命中区域与视觉边界一致。
- 在当前应用支持的 Windows 10/11、WebView2 Runtime环境中验证。

## 9. 验收标准

### 9.1 正常场景

- [ ] 新建影评时拖入一张有效JPG，出现预览并可保存。
- [ ] 拖入PNG和WebP得到与点击选择相同的结果。
- [ ] 编辑已有图片的影评，拖入新图后预览替换；取消编辑后原记录不变。
- [ ] 编辑已有图片的影评，拖入新图并保存后，详情展示新图。
- [ ] 重复拖入同一文件只保留一个哈希媒体文件。
- [ ] 拖入成功后导出ZIP，ZIP包含JSON和当前引用图片；在空数据目录可完整恢复。

### 9.2 错误与边界

- [ ] 同时拖入两张或更多文件时拒绝全部文件，原选择状态不变。
- [ ] 拖入文件夹、TXT、GIF、BMP、ZIP和视频时给出对应错误。
- [ ] JPG扩展名但PNG内容的文件被拒绝。
- [ ] 0字节、恰好50 MB和超过50 MB 1字节的边界行为正确。
- [ ] 拖入后立即取消编辑，不修改 `movie-reviews.json`。
- [ ] 拖入文件在处理前被移动或删除时，不崩溃、不清空旧图片。
- [ ] 从浏览器页面或聊天软件拖入无法获得真实路径的对象时，显示兼容性提示。
- [ ] 拖拽50 MB图片期间窗口保持响应，关闭弹窗后不出现迟到预览。

### 9.3 回归

- [ ] 现有点击“选择剧照”流程保持可用。
- [ ] 无图片影评、详情弹窗、全屏灯箱、编辑、删除、搜索、筛选和统计不受影响。
- [ ] 旧版无图片JSON与现有ZIP备份仍可导入。
- [ ] pywebview仍只显式暴露允许的方法，不公开窗口或存储对象图。
- [ ] 最终EXE无监听端口，个人JSON、`media`和备份不进入Git提交。
